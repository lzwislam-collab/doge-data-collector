此层只读取冻结模型、真实预测账本和 GitHub 实际公开证据，不发行预测、修改账本或切换模型。

## 输出与边界

运行 `python plus_shadow.py`，生成 `plus-shadow-output/report.json` 与可直接打开的 `index.html`。
未生效、未发行或公开预测证据无法核实时不展示方向和概率。概率为冻结模型原始输出，未经真实前瞻校准。
历史目标已到的记录明确标为历史；不会转为新预测。目标留证不合格时不展示准确率或收益。
每张卡的准确率、Brier、基准和成本收益仅对应同一最新事件；不可称为完整历史成绩。
缺成本始终为 null；同事件基准为冻结回放，不冒称原生产系统当时发行的预测。

设置 `PLUS_ASSESSMENT_RUN_ID` 可读取实际成功的 main 完整独立评审，重新验证官方归档摘要、冻结源码及统计重放。
此成绩始终为原评审时点；事件数一致也不证明之后的评分证据一致。未提供评审时，全队列成绩显示未知。
公开归档不等于锁定留存。晋升仍关闭，70%目标尚未证明。

## 自动更新与验收

新增只读 Actions 工作流，跟随现有采集/发行工作流完成后刷新，无新增定时器、Apps Script 触发器或写权限。
分支及 PR 仅离线展示，公开资格不作肯定；main 使用 GitHub 实际回读。手动输入评审 ID 仅作为定位符，不能绕过验证。
完整回归、冻结校验、实际 main 工作流成功和归档摘要/内容回读后，才能确认工程接通。
正式预测发行、目标评分及长期独立证据须等待真实时间；工程展示完成不等于统计目标完成。

## 四层复审补充

### 原十一章报告融合（2026-10-15）

`report_v41.py` 在 F01 展示同次直接读取的 PLUS，F10 按轨道分列最新同事件结果和账本/计划缺口，F11 展示模型身份、输入哈希、核实范围与总体证据状态。没有当前完整独立评审时，全队列准确率仍为未知。原报告不会把最新事件数当成完整评审数。

报告每次调用 `feed_freshness_audit.evaluate` 对当前本地来源重新评估，不改写采集器；旧质量快照仅作时间对照。质量时间戳超过2小时、缺时区、未来时间，以及方向截止不一致均不能形成当前通过结论。可选背景来源失败只降级相关证据，不删除可核实事实。关键日线/评分截止错配仍按原逻辑阻断报告生成。

原有日线工作流直接联网回读 PLUS 证据，未新增调度。离线报告不肯定公开发行资格，适配器异常不读取旧输出兜底。`reports/DOGE_V41_EVIDENCE.json` 保存同次质量与 PLUS 证据。DOWN 展示为“跌／平”；冻结 y、0.5 阈值、成本规则及晋升协议均未改动。

旧评审必须通过当前完整账本在原评审时间的严格重放才可展示；若新事件导致旧评审不适用，成绩栏显示不可用，不借用旧成功标志，也不停止已独立核实的最新预测。离线模式不重查网络或存储审批，版本选择明确未知。
