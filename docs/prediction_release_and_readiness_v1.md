# 运行保障与独立预测版本通道

这是冻结统计协议之外的运行监测和独立预测通道；不改旧模型权重、旧生产指针、既有真实预测账本、生效日期、评分窗口或晋升统计标准，不连接实盘下单。

`forward_readiness.py` 检查三资产完整小时数据的来源、重复、内部缺失、价格/成交量、首次采集与收盘先后、最新闭合小时；检查 R2 漏发、逾期漏评、临近评分截止、当前事件的公开留证，以及原18模型漏发和逾期漏评。历史遗漏不能补造成成功。完整队列的公开证据仍须第三层分批独立重放，本监测只在线重查最新事件，输出明确说明范围。

现有完成回调桥接 Bybit、Binance、小时主采集、两条原有注册审计，无新增 cron 或 Apps Script 触发器。主采集即使辅助步骤失败，也仅在服务端核实冻结防护与核心数据保存成功后请求原发行/评审流程；其他回调必须同仓库 main 成功完成。相同目标已有排队任务时不重复请求，无当前发行或评分需求时不启动预测流程。小时采集回调不能再次请求自身，避免循环。错误先保存再使工作流失败。

GitHub 调度存在实际延迟；互补完成回调不能保证25分钟目标窗口。在缺乏准时外部唤醒证明前，准时运行仍是待验证条件；漏评会保留为失败。分支和 PR 只跑测试，实际时钟检查与派发仅在 main 执行。

`prediction_release_control.py` 提供实际持久化初始冻结参考、候选选择及回退，账本位于 `system/prediction_releases_v1/events`。它不会接管旧生产系统。`infer` 是独立读取和预测接口；当前没有替换旧发行工作流。若参考模型或数据无效，返回不发行；候选过期或审批失效则选择冻结参考。Git 可达历史的追加检查能检测已提交记录修改、删除或断链，不能冒充外部不可改写存储。

流程顺序：

1. `audit` 回读选择，`initialize` 在 main 手动启动一次真实初始参考记录；禁止覆盖。`rollback` 追加回退事件，无下单动作。
2. `prepare` 指定真实完整评审 run，回读官方归档 SHA、成功 main 作业、冻结代码和原始队列并重新计算指标，生成确定性 `evidence.zip` 和 manifest。准备包可以反映门槛尚未通过，不能据此晋升。包包含模型、协议、评审原件、事件、分数、原始目标尝试和绑定记录，未宣称包含仓库全部历史原始源文件，也未证明逐事件目标前 WORM 留存。
3. 实际通过1080个固定计划事件的完整独立前瞻及全部既定门槛后，将确定的 manifest 纳入 `system/prediction_release_manifests_v1`。授权账户在真实仓库 issue/PR 评论写入 `APPROVE_PREDICTION_RELEASE_V1 <manifest SHA256>`，评论须在评审完成之后。系统只读取审批，不能自动发布审批评论。
4. 用户自己的已配置 COMPLIANCE 存储须保存同一证据包，且在 `config/user_managed_prediction_retention.json` 指定实际对象版本、账户、键、保留期限。复用现有 `DOGE_WORM_ROLE_ARN` OIDC 接入执行实际只读验证；不创建或上传资源。取消独立管理方要求，保留实际用户管理留存验证要求。
5. `activate` 只允许明确 main 手动派发；重新读取全部实际评审、账户权限、准确审批、COMPLIANCE 锁和版本字节，任一不足拒绝。读取候选时仍实时重查权限与留存，不能信调用方自封的 approved 标志。当前真实前瞻未开始，晋升必须保持关闭。

操作工作流 `prediction_release_control.yml` 不新增定时器。只提交独立 release 账本，不修改旧生产指针。推送冲突重新取主分支并完整验证，冲突不绕过；实际成功必须以 GitHub 作业、归档回读和提交记录为证，派发接收不等于完成。
