### C. 独立不可改写留存

GitHub 提交、哈希与 90 天 Actions artifact 是有用的留痕，**不是外部不可改写存证**。现有验证器支持 AWS S3 Object Lock 的只读验证，但不能在本项目中无外部账户凭据自动配置真实存储。

启用真实独立存证的外部前置条件：
- 由用户持有、与采集 GitHub 身份权限分离的 AWS 账户/存储账户。此服务**可能计费**，需用户主动授权开通并确认成本与期限。
- S3 bucket 开启版本控制和 Object Lock；针对每个实际字节包写入指定 VersionId，要求 COMPLIANCE 保留模式及明确有效期。
- 预先配置最低保留期限、只读跨账户身份和固定对象身份，不要在聊天里提供访问密钥。
- 真正上传后，使用现有 `pit_retention_preparation.verify_external` 对桶所有权、角色账户、具体 VersionId、读取哈希和锁定状态做实时核验；保留服务器时间回执。只有回读成功的对象才记为 VERIFIED。
- 不得把某个包的锁定证明外推到其他时间的预测；服务器最后修改时间只证明包最迟存在时间，不证明里面历史内容的首次公开时间。

**当前判断：外部独立存证仍为 NOT_CONFIGURED，不能误报已修复。**

### D. 严格的升级验收次序

1. P2源盘口每次运行记录完整缺口和连贯段，不篡改既有P2累计分母或冻结规则。
2. PIT增强特征继续隔离，未来引入时逐源登记首次可用/年龄检查和真实发表证据。
3. 用户明确授权外部存储费用与账户隔离后，再部署独立WORM；以实际云端锁状态和字节回读而非代码测试作为验收。
4. P0发行/到期报价、P1方向与概率、P2纸面净收益各自继续独立审计；不能从工程 PASS 推导预测或盈利 PASS。
